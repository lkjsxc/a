# 文体・ルビの編集方針

## 文体

名称・ナビゲーション・説明は通常のドキュメントの文体に統一します。「目次」「本文」「確認問題」「解答・解説」「関連語」「ダウンロード」など、内容を直接表す語を使用します。比喩的なサービス名、宣伝的な標語、過剰な励まし、機能を目立たせるための造語は使用しません。

本文は知識がない読者にも説明しますが、幼い読者として扱う口調にはしません。専門用語を省くのではなく、必要な定義・具体例を示します。

## 付与する語

一般的な語に一律のルビを付けません。カードの見出しであることや漢字を含むことは、ルビを付ける理由にしません。難読の人名・地名、慣用的な読みを持つ歴史用語、読みを推測しにくい理科用語を`ruby.json`に明示します。

たとえば「気候」「産業」「行政」「反射」「酸化」は原則として対象外です。「凡例」「勅許」「胚珠」「絨毛」「翅」などは対象にします。読者の知識には差があるため、辞書は今後の具体的な指摘に応じて編集します。漢字学年だけによる自動判定は行いません。

## 付与位置

本文は節の初出を基本とします。見出しと本文は別に扱い、見出しを飛ばして読んでも読みを確認できるようにします。用語表のセル・個別の確認問題・Ankiカードは独立して読まれるため、それぞれで読みを示します。

単語全体を優先します。既存のルビを除いてから長い語を先に照合するため、「二酸化炭素」の「酸化」だけにルビを付けることはありません。漢字・英数字・カタカナに接する語は、登録語全体であると確認できなければ自動付与しません。

「明」「清」「元」「周」「調」など文脈によって意味や読みが変わる短い語は、一律の辞書に登録しません。別名の読みを別の表記へ付けることも禁止します。たとえば「戦後の家電」に「さんしゅのじんぎ」を付けず、実際に書かれた「三種の神器」に付けます。

辞書にない語・文脈依存の読みが必要になった場合は、まず原稿と読みを確認し、曖昧さのない語句を辞書へ追加します。HTML属性、URL、コード、タグそのものにはルビを付けません。

## データの保持・検証

ルビを取り除いた本文、教材ID、カードID、選択カードの構成は維持します。辞書の変更後は`site/normalize-content.ts`で理科・既存カードを正規化し、社会の生成器で本文・APKG・CSV・TSV・オフラインHTML・ZIPを再生成します。

理科の旧データには、閉じHTMLタグのスラッシュを区切りと誤認して関連語配列が壊れた箇所がありました。改訂では裏面にある関連語の基底文字列から復元し、タグの断片が配列へ残らないことを確認しています。

`migration.json`は2026年10月1日の移行前後の記録です。再実行時に初回の記録を上書きしません。単体テストでは部分付与、曖昧な単字、初出、独立セル、属性・コードの保護、二重ルビ、再実行の同一性を検査します。

ルビの付け方を整理したことは、教材全体の専門家査読や入試難易度の保証を意味しません。
